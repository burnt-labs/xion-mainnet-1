# Xion v33 Release Notes

## Overview

Xion v33 upgrades xion-mainnet-1 from v32. Mainnet runs `v33.0.1`, tagged on [`eb86339`](https://github.com/burnt-labs/xion/commit/eb863391517e129ae2b5979f582b04b81e9bed69), the same commit as `v33.0.0-rc2`. xion-testnet-2 upgrades to v33 with `v33.0.0-rc2` at height 19487000 ([proposal 067](https://github.com/burnt-labs/xion-testnet-2/pull/55), passed). `v33.0.0` was published without binaries, so the mainnet release is `v33.0.1`; no code differs between them.

## What's Changed

### Upgrade Handler

- Upgrade name `v33`. No stores are added, renamed or deleted.
- Runs the module migrations, then rewrites the fee allowance queue entries that the pre-v32 feegrant module stored with an empty value to the encoding the v0.55 feegrant module reads ([xion#703](https://github.com/burnt-labs/xion/pull/703)). Without it, the feegrant EndBlocker fails to decode such an entry once it expires. xion-mainnet-1 holds 9 of them, all from before v32; grants created since v32 already use the current encoding. Entries that already hold a value are left unchanged.

### Node

- `xiond start` applies its 1 s `consensus.timeout_commit` default over `config.toml` unless `--consensus.timeout_commit` or `XIOND_CONSENSUS_TIMEOUT_COMMIT` is set ([xion#696](https://github.com/burnt-labs/xion/pull/696)).
- `xiond start --trace-store <file or FIFO>` is accepted again, for state indexers that read committed store writes ([xion#697](https://github.com/burnt-labs/xion/pull/697)).

### Dependencies

- None changed since v32.0.0.

## Node Operators

- With Cosmovisor, place the binary at `upgrades/v33/bin/xiond`; `releases/v33.json` lists the binaries with checksums.
- No config or DB migration step. Release Linux binaries are fully static.

## Integrators

- No API, query or transaction format changes.
